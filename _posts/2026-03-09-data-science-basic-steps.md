許多人一聽到資料科學，首先想到的是 `Python`、`機器學習` 與 `模型準確率`。

但實際觀察資料科學專案的執行方式後，會發現工作通常不是從模型開始。更常見的情況是先提出一個模糊問題，再將它拆解成可回答的問題、找到對應資料、整理成可分析的格式，最後將結果轉化為團隊可以採取行動的答案。

因此，如果要用一句話說明資料科學，我會這樣描述：

**資料科學不是一開始就建立模型，而是將「問題」逐步轉化為「可以支援決策的資訊」。**

---

# 1. 資料科學不是只有建模

這是初學者最容易產生的誤解。

許多人將資料科學想像成「取得資料、輸入模型、得到答案」。這種理解並非完全錯誤，卻忽略了專案中最耗時、也最容易出現問題的環節。

實際工作通常包括：

- 釐清真正需要解決的問題。
- 定義需要觀察的指標。
- 確認資料來源是否足夠。
- 清理無法直接使用的原始資料。
- 分析資料並向他人說明結果。
- 根據結果制定決策，必要時再回頭修正問題定義。

![資料科學不是只有建模，而是一整條從問題到決策的流程](/assets/images/260314/data-science-not-just-modeling.svg?v=2)

_圖：左側呈現常見想像，右側則更接近真實專案。建模可能很重要，但只是整體流程中的一個環節。_

如果一開始的問題定義錯誤，後續模型再精巧也無法產生正確價值。
如果資料口徑混亂，再複雜的分析也只會更精細地計算錯誤內容。

# 2. 從圖中理解資料科學的五個基本步驟

原始參考圖很適合作為入門流程。

我將它重構為較完整的版本，保留原本五個主要步驟，並補上經常被省略的兩個環節：`定義問題` 與 `採取行動`。

![資料科學的基本步驟：從定義問題到採取行動](/assets/images/260314/data-science-basic-steps.svg?v=2)

_圖：這張圖在原始流程前後各補上一個環節。資料科學真正的起點不是蒐集資料，而是定義問題；終點也不是完成圖表，而是根據結果採取行動。_

## 2.1 資料蒐集

許多人將這一步理解為「取得資料」。

但更精確地說，這一步是在判斷：為了回答目前的問題，究竟需要哪些資料。
如果問題是會員流失，可能需要查看登入、購買與客服紀錄。
如果問題是轉換率下降，則需要查看流量來源、加入購物車、結帳與付款失敗等資料。

因此，資料蒐集的核心不是越多越好，而是能否取得與問題真正相關的資料。

## 2.2 資料清理

原始資料很少能直接用於分析。

常見問題包括：

- 缺失值。
- 重複資料。
- 日期與時間格式不一致。
- 同一事件在不同系統中使用不同名稱。
- 欄位看似相同，定義口徑卻不一致。

資料清理的目的，是將原始紀錄整理成可信任且可重複使用的分析基礎。

## 2.3 資料儲存

這一步經常被低估，卻是資料能否持續使用的關鍵。

如果資料散落在 Excel、CSV、表單匯出檔或聊天紀錄中，或許能完成一次分析，卻很難穩定地再次執行。
將資料存入資料表、資料庫或結構化資料倉儲，不是為了形式上的專業，而是為了讓分析可以重現、維護並持續更新。

## 2.4 資料分析

這是大多數人最熟悉的步驟。

但資料分析不一定要使用機器學習。許多真正有價值的分析可能只是：

- 比較兩組使用者的行為差異。
- 觀察特定期間的趨勢。
- 找出轉換漏斗中流失最多的階段。
- 判斷哪些欄位與結果關係最密切。

模型固然是重要工具，但並非每個問題都需要使用模型。

## 2.5 資料視覺化

視覺化的目的不只是讓圖表美觀，更要讓他人真正理解資訊。

如果資料科學的成果只停留在 Notebook 中的一串數字，對團隊幫助有限。
真正有用的視覺化，會將分析結果轉化為產品經理、工程師、主管與營運人員都能快速理解的形式，加快後續決策。

# 3. 以電商案例串連完整流程

如果上述五個步驟仍顯抽象，可以透過具體情境將流程串連起來。

假設某個電商網站的團隊發現近期轉換率下降。
此時，資料科學工作不應直接跳到預測模型，而應先依照完整流程釐清問題。

![用電商網站轉換率下降的案例示範資料科學流程](/assets/images/260314/data-science-ecommerce-example.svg?v=2)

_圖：這個案例刻意不使用複雜模型，而是透過常見業務問題檢視完整流程。資料科學更接近拆解問題，而不是一開始就套用演算法。_

在這個案例中：

- 蒐集階段需要取得完整的流量、商品頁、購物車、結帳與付款紀錄。
- 清理階段需要統一事件名稱與時間格式，並處理重複資料。
- 儲存階段需要將資料放入可重複執行分析的資料表。
- 分析階段需要找出流失最嚴重的步驟。
- 視覺化階段需要讓團隊迅速看出問題集中之處。

最後，這套流程真正要產生的不是一張圖，而是具體行動：
例如優先修正付款流程，而不是繼續漫無目的地猜測原因。

# 4. 為什麼初學者最容易受阻於前三個步驟

許多人學習資料科學一段時間後會產生落差感，原因通常不是演算法太難，而是實際工作內容與原先想像不同。

原本以為工作會持續建立模型，實際上卻經常需要：

- 使用 SQL 查詢資料。
- 對齊欄位定義。
- 確認資料來源是否可靠。
- 檢查指標的定義口徑是否改變。
- 與相關人員確認事件代表的實際意義。

這些工作並未偏離主題，而是資料科學本身的重要部分。

![資料科學常見的工作分配示意圖](/assets/images/260314/data-science-time-split.svg?v=2)

_圖：圖中的比例僅為示意，但呈現的方向很重要。初學者最容易低估的往往是資料整理、驗證與溝通，而不是建模本身。_

如果一開始就理解這項特性，反而較不容易感到焦慮。
資料科學真正需要的，是清楚定義問題、妥善整理資料，並向他人說明結果的能力。

# 5. 初學者應該先學什麼

對剛入門的讀者，我建議按照基礎到進階的順序學習。

比起急著學習最複雜的模型，更應該先穩固以下幾項基礎：

- `SQL`
  先學會查詢資料、執行 Join 與 Group By。這些技能通常比一開始學習深度學習模型更常用。
- `資料整理`
  無論使用 `pandas`、`polars` 或其他工具，重點都是將資料轉換成可分析的格式。
- `基本統計`
  平均數、中位數、分布、變異、相關性與抽樣等概念，比許多人想像中更重要。
- `圖表與溝通`
  能否清楚說明結果，往往比是否多掌握一種模型更加關鍵。
- `問題定義`
  先釐清真正需要回答的問題，往往比選擇模型更加重要。

如果這些基礎尚未穩固，過早將重心放在模型上，可能只會產生資料科學工作的表象，卻未真正解決問題。

---

# 6. 結語

資料科學最常見的誤解，是將它視為華麗的技術工作；但其真正核心是一套務實流程：

**定義問題、取得資料、整理資料、分析資料，再將結果轉化為決策。**

因此，如果要向完全沒有相關經驗的人解釋資料科學，我建議不要從模型開始。
直接從這套流程說明，反而更接近資料科學的日常工作。

資料科學最終要交付的，不是一個看似厲害的模型名稱，而是團隊能夠據以行動的答案。
