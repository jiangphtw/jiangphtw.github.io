剛接觸資料科學時，我曾學到兩項重要觀念，至今仍然適用。

第一，`統計` 的價值不只在於計算公式，更在於協助人們在資訊不完整時做出較可靠的判斷。
第二，`資料視覺化` 不只是美化圖表，而是讓人真正看見資料中的模式、異常與脈絡。

許多初學者將兩者分開看待，彷彿資料分析只負責計算數字，而資料視覺化只用來製作簡報。
但在實務上，兩者通常是同一套流程的前後階段：先分析資料並找出值得解釋的模式，再透過視覺化呈現，讓自己與他人都能理解。

本文將分別說明資料分析與資料視覺化，最後提供幾組可自行練習的題目。

---

# 1. 什麼是資料分析

資料分析不是將資料輸入 `pandas` 就算完成。
它真正要做的，是將模糊問題轉化為一組可以檢查、比較與解釋的結果。

例如：

- 營收是否下降？
- 所有通路都在下降，還是只有特定通路？
- 原因是流量減少，還是轉換率降低？
- 這是短期波動，還是真的出現結構性問題？

換句話說，資料分析的核心不是程式碼，而是 `問題拆解能力`。

![資料分析與資料視覺化的分工](/assets/images/260315/analysis-vs-visualization.svg)

_圖：資料分析負責把問題拆成可驗證的指標，資料視覺化負責把模式與差異呈現出來。_

## 1.1 敘述性分析與推論性分析

依照最基本的分類方式，資料分析可以分為兩類：

### 敘述性分析

這類分析用來回答：

- 資料目前呈現什麼樣貌？
- 平均值、中位數、比例與分布如何？
- 哪個類別數量最多？
- 本週與上週相差多少？

它的作用是 `摘要資料`。
例如，整理每日訂單數、平均客單價與退貨率，就是敘述性分析。

### 推論性分析

這類分析在回答：

- 這項差異是否可能只是隨機波動？
- 從樣本觀察到的結果能否推論至母體？
- 特定因素與結果之間是否存在關聯？
- 觀察到的變化是否足以支持某項假設？

它的作用是協助 `建立判斷`。
例如，比較兩個廣告版本的轉換率差異是否顯著，就屬於推論性分析。

## 1.2 資料分析通常如何進行

一套穩定的分析流程，通常至少包含以下步驟：

1. 定義問題。
2. 定義分析單位。
3. 選擇指標。
4. 切分並比較資料。
5. 檢查異常與離群值。
6. 整理結論。

![從問題到結論的資料分析流程](/assets/images/260315/analysis-process-from-question-to-insight.svg)

_圖：分析不是直接產生圖表，而是從問題、指標、切分與比較逐步形成可解釋的結論。_

其中最容易被忽略的是第二步：`分析單位`。
如果分析對象是使用者，就不能將同一個人的多次事件視為彼此獨立；如果分析對象是訂單，就不能直接從 Session 的角度解讀。

許多分析結果之所以越來越混亂，不是因為圖表選擇錯誤，而是一開始就混用了分析單位。

# 2. 什麼是資料視覺化

資料視覺化不是裝飾。
其最重要的功能，是將原本只能逐列閱讀的數字，轉化為能快速辨識模式的形式。

如果直接呈現大量數字，讀者很難立即看出異常。
但將相同資料繪製成圖表後，通常可以迅速發現：

- 哪個位置突然升高？
- 哪些群組差異很大？
- 哪個資料點是離群值？
- 趨勢正在上升、下降，還是僅在區間內波動？

因此，良好視覺化的目的不只是美觀，而是 `降低判讀成本`。

## 2.1 視覺化有兩種主要用途

### Exploration

此時尚未知道答案，只想先觀察資料中是否存在值得注意的規律。

這時可以利用圖表提出以下問題：

- 哪個通路的表現特別差？
- 某個地區是否存在離群值？
- 某個類別的分布是否偏斜？
- 特定變數是否可能與結果相關？

### Storytelling

此時已經找到重點，需要向他人清楚說明。

這時可以利用圖表說明：

- 問題出現在哪裡？
- 差異有多大？
- 變化從何時開始？
- 哪個群體受到的影響最大？

![視覺化選圖要先看你在回答什麼問題](/assets/images/260315/chart-selection-by-question.svg)

_圖：不要先決定使用長條圖或折線圖，而應先判斷需要回答的是趨勢、比較、分布、關聯還是組成問題。_

## 2.2 初學者最常犯的視覺化錯誤

- 在一張圖中放入過多資訊。
- 使用太多顏色，卻沒有呈現主次關係。
- 圖表軸標示不完整。
- 將不適合比較的項目放在一起比較。
- 使用圓餅圖呈現細微差異。
- 只顧美觀，未先考慮讀者需要查看的資訊。

資料視覺化真正的標準不在於是否漂亮，而在於 `讀者能否快速理解重點`。

# 3. 資料分析與視覺化如何相互配合

最常見的錯誤流程是：

1. 先開啟圖表工具。
2. 任意加入幾個欄位。
3. 產生看似完整的圖表。
4. 實際上卻沒有回答問題。

較合適的流程通常是：

1. 先定義需要回答的問題。
2. 再決定需要哪些指標。
3. 接著決定如何切分與比較資料。
4. 最後才選擇圖表類型。

例如，如果問題是「網站轉換率下降是否來自特定流量來源」，分析與視覺化可以採用以下方式配合：

- 分析：
  先計算各來源的 `sessions`、`orders` 與 `conversion_rate`。
- 視覺化：
  先以折線圖觀察時間趨勢，再用分組長條圖比較不同來源。

如果問題是「客服回覆時間是否降低滿意度」，可以採用以下方式：

- 分析：
  計算每張工單的 `first_response_minutes` 與 `csat`。
- 視覺化：
  先查看分布，再使用散點圖或分組盒鬚圖。

換句話說，圖表不是分析的替代品，而是分析完成後的重要判讀介面。

# 4. 良好的圖表通常回答五類問題

如果不知道應選擇哪種圖表，建議不要從圖表名稱開始，而要先確認需要回答哪一類問題。

## 4.1 趨勢

需要回答的問題包括：

- 是否呈現上升或下降趨勢？
- 變化從何時開始？
- 哪些時間點出現突然波動？

常見圖表：

- 折線圖。
- 面積圖。

## 4.2 比較

需要回答的問題包括：

- 哪一組較高、哪一組較低？
- 差異有多大？
- 排名如何？

常見圖表：

- 長條圖。
- 分組長條圖。

## 4.3 分布

需要回答的問題包括：

- 數值集中在哪個範圍？
- 分布是否偏斜？
- 是否存在離群值？

常見圖表：

- 直方圖。
- 盒鬚圖。
- 密度圖。

## 4.4 關聯

需要回答的問題包括：

- 兩個變數是否共同變動？
- 當某個值提高時，另一個值是否隨之改變？

常見圖表：

- 散點圖。
- 氣泡圖。

## 4.5 組成

需要回答的問題包括：

- 整體由哪些部分構成？
- 各部分比例如何變化？

常見圖表：

- 堆疊長條圖。
- 堆疊面積圖。

圓餅圖並非不能使用，但若要比較細微差異，長條圖通常更加清楚。

# 5. 三組動手練習題

本文不直接提供標準答案，而是設計接近真實工作的練習。
可以使用 `Excel`、`Google Sheets`、`SQL` 或 `pandas`，重點是同時練習問題分析與視覺化表達。

![資料分析與資料視覺化練習題設計](/assets/images/260315/analysis-visualization-practice-lab.svg)

_圖：練習不應只產生一張圖，而應涵蓋問題定義、指標計算、圖表選擇與文字結論。_

## 練習 1：電商流量與轉換率

假設有一份包含以下欄位的資料表：

- `date`
- `channel`
- `sessions`
- `orders`
- `revenue`
- `ad_spend`

請完成以下工作：

1. 計算每天各通路的 `conversion_rate`。
2. 計算 `ROAS`。
3. 找出最近兩週表現明顯變差的通路。
4. 繪製一張折線圖觀察趨勢。
5. 再繪製一張長條圖，比較最近 7 天的表現。
6. 以 100 至 150 字撰寫結論。

這道題目練習的是：

- 趨勢分析。
- 比較分析。
- 指標定義。
- 使用同一份資料，以不同圖表回答不同問題。

## 練習 2：客服工單與滿意度

假設欄位如下：

- `ticket_id`
- `product_line`
- `priority`
- `created_at`
- `first_response_minutes`
- `resolved_minutes`
- `csat_score`

請完成以下工作：

1. 查看 `first_response_minutes` 的分布。
2. 比較不同 `priority` 的處理時間差異。
3. 檢查處理時間與 `csat_score` 是否存在關聯。
4. 找出具有離群值的工單，並說明處理方式。
5. 製作一張供主管查看的圖表，說明最值得優先改善的流程。

這道題目練習的是：

- 分布判讀。
- 盒鬚圖與散點圖的使用。
- 離群值處理。
- 從探索分析形成可溝通的結論。

## 練習 3：門市來客、促銷與天氣

假設欄位如下：

- `store_id`
- `date`
- `foot_traffic`
- `transactions`
- `promotion_flag`
- `avg_temp`
- `rainfall_mm`

請完成以下工作：

1. 計算每日轉換率 `transactions / foot_traffic`。
2. 比較促銷與未促銷期間的差異。
3. 檢查雨量與來客數是否存在明顯關聯。
4. 找出表現最穩定及波動最大的門市。
5. 選擇兩張最合適的圖表，製作一頁簡短報告。

這道題目練習的是：

- 關聯分析。
- 分群比較。
- 變異與穩定度判讀。
- 使用少量圖表清楚說明業務問題。

---

# 6. 進行練習時應特別檢查什麼

如果想讓這些練習更接近真實分析，我建議完成每道題目後，都重新檢查以下事項：

- 目前究竟在回答哪個問題？
- 選用的指標是否定義清楚？
- 比較對象是否屬於相同分析單位？
- 這張圖用於探索還是溝通？
- 如果只保留一張圖，它能否支持結論？
- 其他人查看這張圖時，是否可能產生誤解？

這些問題比使用哪個套件更加重要。

# 7. 結語：資料分析與資料視覺化應該一起學習

資料分析訓練人們提出正確問題、拆解合適指標並判讀差異。
資料視覺化則讓模式得以呈現、結論易於理解。

如果只學習分析而不學視覺化，很容易產生只有自己能理解的結果。
如果只學習視覺化而不學分析，則容易建立看似完整、實際上卻未回答問題的圖表。

因此，更合適的學習方式不是二選一，而是同時練習：

- 先定義問題。
- 再計算指標。
- 接著選擇圖表。
- 最後寫出真正具有判斷力的結論。

**真正良好的圖表，背後必然有清楚的分析；真正良好的分析，也幾乎都需要視覺化協助呈現。**
