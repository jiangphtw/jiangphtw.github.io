資料科學入門我曾學過兩個重要的提醒到現在還是很準。

第一，`統計` 的價值不是把公式算出來，而是幫你在不完整資訊下做比較可靠的判斷。  
第二，`資料視覺化` 不是把圖畫漂亮，而是讓你真的看見資料裡的模式、異常與故事。

很多初學者會把這兩件事拆開看，好像資料分析是算數字，資料視覺化是做簡報。
但實務上，它們通常是同一條流程的前後兩段：你先分析資料，找出值得解釋的模式；再用視覺化把模式呈現出來，讓自己和別人都看懂。

這篇就把資料分析與資料視覺化拆開講清楚，最後也附上幾組可以自己動手練的題目。

---

# 1. 什麼是資料分析

資料分析不是「把資料丟進 `pandas`」就算完成。
它真正要做的是把一個模糊問題，轉成一組可以被檢查、比較、解釋的結果。

例如：

- 營收下降了嗎
- 是所有通路都下降，還是只有某個通路
- 是流量變少，還是轉換率變差
- 是短期波動，還是真的出現結構性問題

也就是說，資料分析的核心不是程式碼，而是 `問題拆解能力`。

![資料分析與資料視覺化的分工](/assets/images/260315/analysis-vs-visualization.svg)

_圖：資料分析負責把問題拆成可驗證的指標，資料視覺化負責把模式與差異呈現出來。_

## 1.1 敘述性分析與推論性分析

如果用最基本的方式分，資料分析常會分成兩類：

### 敘述性分析

這類分析在回答：

- 資料現在長什麼樣
- 平均值、中位數、比例、分布如何
- 哪個類別最多
- 這一週和上一週差多少

它是在幫你 `摘要資料`。
例如把每日訂單數、平均客單價、退貨率整理出來，這就是敘述性分析。

### 推論性分析

這類分析在回答：

- 這個差異有沒有可能只是隨機波動
- 從樣本看到的結果，能不能推到整體
- 某個因素和結果之間有沒有關聯
- 觀察到的變化，是否足以支持某個假設

它是在幫你 `建立判斷`。
例如比較兩個廣告版本的轉換率差異是否顯著，就已經開始進入推論。

## 1.2 資料分析通常怎麼進行

一個穩定的分析流程，通常至少包含下面幾段：

1. 定義問題
2. 定義分析單位
3. 選指標
4. 做切分與比較
5. 檢查異常與例外值
6. 整理成結論

![從問題到結論的資料分析流程](/assets/images/260315/analysis-process-from-question-to-insight.svg)

_圖：分析不是直接跑圖，而是從問題、指標、切分、比較一路走到可解釋的結論。_

這裡最容易被忽略的是第二步：`分析單位`。
如果你今天分析的是使用者，就不能把同一個人多次事件當成彼此獨立；如果你分析的是訂單，就不能直接用 session 的角度去解讀。

很多分析之所以後面越看越亂，不是因為圖選錯，而是一開始單位就混了。

# 2. 什麼是資料視覺化

資料視覺化不是裝飾。
它最重要的功能，是把一堆本來只能一列一列讀的數字，變成你能夠快速發現模式的形式。

如果我把一大串數字直接丟給你，你很難一眼看出哪裡異常。  
但如果把同樣的資料畫成圖，你通常會立刻看到：

- 哪裡突然跳高
- 哪幾群差異很大
- 哪一個點是異常值
- 趨勢是上升、下降，還是只是震盪

這也是為什麼好的視覺化，不是為了「好看」，而是為了 `降低判讀成本`。

## 2.1 視覺化有兩種主要用途

### Exploration

你還不知道答案，只是想先看看資料裡有沒有值得注意的規律。

這時候你會用圖表來問：

- 哪個通路表現特別差
- 某個地區是不是有異常值
- 某個類別的分布是不是偏斜
- 某個變數和結果有沒有可能相關

### Storytelling

你已經找到重點了，現在要把它講清楚給別人聽。

這時候你會用圖表來說：

- 問題在哪裡
- 差異多大
- 變化何時開始
- 哪個群體受影響最大

![視覺化選圖要先看你在回答什麼問題](/assets/images/260315/chart-selection-by-question.svg)

_圖：不是先想用長條圖還折線圖，而是先想你要回答趨勢、比較、分布、關聯，還是組成。_

## 2.2 初學者最常犯的視覺化錯誤

- 一張圖塞太多訊息
- 配色太多，卻沒有主次
- 軸標示不完整
- 把不適合比較的東西放在一起比較
- 用圓餅圖硬講細微差異
- 只顧著美觀，沒有先想讀者要看什麼

資料視覺化真正的標準不是「漂亮」，而是 `看的人能不能快速理解重點`。

# 3. 資料分析與視覺化怎麼互相配合

最常見的錯誤流程是：

1. 先開圖表工具
2. 隨便拉幾個欄位進去
3. 看起來像有圖了
4. 但其實沒有回答問題

比較好的流程通常是：

1. 先定義要回答的問題
2. 再決定需要什麼指標
3. 再決定要怎麼切分比較
4. 最後才決定用什麼圖

舉例來說，如果問題是「網站轉換率下降是不是來自某個流量來源」，那分析與視覺化可以這樣配：

- 分析：
  先算每個來源的 `sessions`、`orders`、`conversion_rate`
- 視覺化：
  先用折線圖看時間趨勢，再用分組長條圖比較不同來源

如果問題是「客服回覆時間是不是拖慢滿意度」，那你可能會：

- 分析：
  算每張工單的 `first_response_minutes` 與 `csat`
- 視覺化：
  先看分布，再看散點圖或分組盒鬚圖

也就是說，圖表不是分析的替代品，而是分析完成後最重要的判讀介面。

# 4. 一個好圖表，通常先回答五種問題

如果你不知道該選什麼圖，我很建議先不要從圖名開始，而是先問自己：我到底要回答哪一類問題？

## 4.1 趨勢

你在問的是：

- 有沒有上升或下降
- 變化從什麼時候開始
- 哪些點有突然波動

常見圖表：

- 折線圖
- 面積圖

## 4.2 比較

你在問的是：

- 哪一組高、哪一組低
- 差多少
- 排名如何

常見圖表：

- 長條圖
- 分組長條圖

## 4.3 分布

你在問的是：

- 數值集中在哪裡
- 有沒有偏態
- 有沒有異常值

常見圖表：

- 直方圖
- 盒鬚圖
- 密度圖

## 4.4 關聯

你在問的是：

- 兩個變數有沒有一起變動
- 某個值提高時，另一個值會不會跟著變

常見圖表：

- 散點圖
- 氣泡圖

## 4.5 組成

你在問的是：

- 整體由哪些部分構成
- 各部分比例怎麼變化

常見圖表：

- 堆疊長條圖
- 堆疊面積圖

圓餅圖不是不能用，但如果你要比較細微差異，通常長條圖更清楚。

# 5. 三組自己動手做的練習題

這裡我不直接給你標準答案，而是給你一組接近真實工作的練習設計。
你可以用 `Excel`、`Google Sheets`、`SQL`、`pandas` 都行，重點是把「分析問題」和「視覺化表達」一起練。

![資料分析與資料視覺化練習題設計](/assets/images/260315/analysis-visualization-practice-lab.svg)

_圖：練習不要只做一張圖，而是練問題定義、指標計算、圖表選擇與文字結論。_

## 練習 1：電商流量與轉換率

假設你有一份表，欄位如下：

- `date`
- `channel`
- `sessions`
- `orders`
- `revenue`
- `ad_spend`

請你做這些事：

1. 算出每天、每個通路的 `conversion_rate`
2. 算出 `ROAS`
3. 找出哪個通路在最近兩週明顯變差
4. 畫一張折線圖看趨勢
5. 再畫一張長條圖比較最近 7 天的表現
6. 用 100 到 150 字寫出你的結論

這題在練的是：

- 趨勢分析
- 比較分析
- 指標定義
- 同一份資料用不同圖表回答不同問題

## 練習 2：客服工單與滿意度

假設欄位如下：

- `ticket_id`
- `product_line`
- `priority`
- `created_at`
- `first_response_minutes`
- `resolved_minutes`
- `csat_score`

請你做這些事：

1. 看 `first_response_minutes` 的分布
2. 比較不同 `priority` 的處理時間差異
3. 檢查處理時間和 `csat_score` 是否有關聯
4. 找出異常值工單，並說明你打算怎麼處理
5. 做一張給主管看的圖，說明哪一段流程最值得優先改善

這題在練的是：

- 分布判讀
- 盒鬚圖與散點圖的使用
- 異常值處理
- 從探索走到可溝通結論

## 練習 3：門市來客、促銷與天氣

假設欄位如下：

- `store_id`
- `date`
- `foot_traffic`
- `transactions`
- `promotion_flag`
- `avg_temp`
- `rainfall_mm`

請你做這些事：

1. 算每日轉換率 `transactions / foot_traffic`
2. 比較有促銷和沒促銷的差異
3. 看雨量和來客數有沒有明顯關聯
4. 找出表現最穩定與波動最大的門市
5. 選兩張最適合的圖，做一頁簡短報告

這題在練的是：

- 關聯分析
- 分群比較
- 變異與穩定度判讀
- 用少量圖表講清楚一個業務問題

# 6. 做練習時，我會特別檢查什麼

如果你想把這些練習做得更像真實分析，我會建議每做完一題，都回頭檢查下面幾件事：

- 我現在到底在回答哪個問題
- 我選的指標有沒有定義清楚
- 我的比較對象是不是同一個分析單位
- 這張圖是在探索，還是在溝通
- 如果只留一張圖，它能不能支持我的結論
- 如果別人看這張圖，他會不會誤解

這幾題比你用了哪個套件更重要。

# 7. 寫在最後：資料分析和資料視覺化，本來就該一起學

資料分析教你怎麼問對問題、拆對指標、判讀差異。  
資料視覺化教你怎麼讓模式被看見、讓結論被理解。

如果只學分析，不學視覺化，你很容易做出只有自己看得懂的結果。  
如果只學視覺化，不學分析，你很容易做出看起來很完整，但其實沒有回答問題的圖。

所以更好的學法不是二選一，而是一起練：

- 先定義問題
- 再算指標
- 再選圖
- 最後寫出一句真正有判斷力的結論

**真正好的圖表，背後一定有清楚的分析；真正好的分析，也幾乎都需要視覺化來幫你看見它。**
